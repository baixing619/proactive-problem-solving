# 实际记录能支持哪些用途

这里是日常工作记录中的行为观察，用来解释技能要求怎样落到具体行动。它不是有技能/无技能的对照实验，不能证明改善来自这一个技能，也没有计算成功率、节省时间或 token 收益。

## 开源前，先核对实际文件

一次本地工具开源咨询中，读取项目文件并检查入口存在性，发现启动脚本寻找的程序位置与发布目录不一致，构建入口没有覆盖完整源码，另有本机专用路径。

有用的交付是有文件证据的发布前问题清单，让下一步修复有明确位置。该轮没有编译、启动或上传，所以不能把问题清单称为软件已经修好或开源完成。

## 修复之后，验证状态真的改变了

一次本地后台停止入口开发中，候选程序先后出现脚本解析、默认路径和回执问题。记录显示代理检查具体错误、核对管道语义、修改实现，再用最终候选做安全验证：主线程阻塞时，所属后台实际退出；停止后的自动重建被拒绝。

该验证没有触发真实业务动作。它证明候选的局部停止行为，正在使用的旧窗口还没加载新版本，因此不能说现行程序已生效。这体现了“修复证据”和“最终交付证据”需要分别核对。

## 数据不一致时，先收窄结论

一次表格资料核对中，旧格式文件缺少读取依赖。补齐必要读取能力后，发现价格表不同页的旧价口径不同，进货明细另有重复页。用户质疑价格判断后，代理重新读取表头和原单元格，改为指出记录差异并要求先统一可比口径。

有用的进展是明确下一步需要核实什么，避免带着不一致的价格继续计算。完整预算和月度节省结果没有在该轮完成。

## 如何复核这些例子

从上一完整七天中，29 个确认读取技能的代理会话各取首次读取事件，按会话哈希排序后，以固定种子 `20261006` 随机抽取 8 个会话。保留原抽样，不替换成成功案例；从读取前后行动、工具返回和最终说明核对结果。两名独立审核代理各检查一半，主代理复核了说明所需的文件与结果证据。

8 个样本包含 3 个用户来源的任务片段和 5 个子代理任务；其中一个是续跑，先前自动注入的目标上下文不能算真人介入。抽取器没有可靠保留部分子代理的完整委派正文，长工具输出有节选，图像像素也不在文本样本中。因此没有把它们当作 8 个独立用户任务，更没有绘制完成率图。上面选的是能说明具体行为、且公开后不包含私有项目内容的三个例子，不代表样本总体效果。

记录还显示，读取技能后仍可能一度偏离用户重点或作出过强判断，需要接受纠正。这份指导并不能替代模型能力、授权条件、直接证据或用户验收。

原始对话、账号、私有路径、业务数值和审计事件索引保留在本地，没有随仓库发布。公开例子经过脱敏；外部读者无法仅凭本仓库独立重算原始观察，应该将其视为作者自报、经过本地复核的有限案例，而不是公开基准数据。

## 第一次使用时看什么

选择一个你本来要做、但卡住的具体任务，写明目标和不能改变的条件，显式调用技能。观察：

- 是否把障碍定位到可以检验的层面，并拿到新证据？
- 没有进展时，是否改变了验证方法，而非换措辞盲试？
- 成功后，是否读回了目标对象或实际状态？
- 未完成时，是否准确保留完成部分和真实阻塞点？

这些是可以检查的行为和结果信号。个人读取频率只能说明使用情况，不能替代上述证据。

若你也苦于任务过早被标记“受阻”，可按 [效果比较与记录口径](evaluation.md) 分开记录可避免受阻、用户纠错、实际代做和必要授权。该文同时说明现有案例能支持的障碍前后对照，以及哪些效率或接管改善尚无法计算。
