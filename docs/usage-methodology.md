# 七天个人本地技能读取观察

统计窗口：北京时间（UTC+08:00）2026-09-29 00:00:00 至 2026-10-06 00:00:00，结束时刻不包含在内。当前开源任务发生于结束时刻之后，自然排除；同一既有会话在窗口内的普通工作保留。

## 结果

- 有真实 assistant 工具调用活动的 session：40。
- 至少有一次确认技能读取的 session：35。
- 确认读取的不同技能目录名：25；确认的“工具调用 × 技能”读取事件：423。
- `proactive-problem-solving`：29 个 session、128 次确认读取，按 session 去重计数排名第 1。
- 占工具活动 session 的 72.50%（29/40）；占确认读取任意技能的 session 的 82.86%（29/35）。

这里的 session 是 rollout 元数据的 session ID，不是 40 个独立用户对话。符合窗口条件的子代理、分叉 session 同样可能进入样本。一个 session 可读取多个技能，因此各技能占比不能相加；一个 session 可在多天活动，因此每日 session 计数不能相加得到七天去重计数。

## 采集与判定

1. 在个人本地 Codex sessions 目录中枚举 `.jsonl`；本次快照共有 1,693 个文件。以文件修改时间不早于窗口开始作预筛，共扫描 77 个文件，随后严格检查每条事件自己的 UTC 时间。这样会保留最近续写的旧会话，避免仅按文件创建日期筛选。恢复或复制时人为保留旧修改时间的文件可能漏掉；脚本提供 `--scan-all` 关闭预筛选。本次没有把其余文件都解析成事件。
2. 只取 `response_item` 中真正的 `function_call` / `custom_tool_call`。较新的本地格式常用 `custom_tool_call`，命令在 `input`；传统格式使用 `arguments`。`event_msg.item_completed` 等完成事件镜像不计，message、system/developer/user 内容和技能目录 catalog 中的提及也不计。
3. 支持直接 shell 工具命令，以及 `exec` 中嵌套的静态 `cmd` / `command` 字符串与简单静态绑定。识别 `Get-Content`、`cat` / `type`、`ReadAllText`、`read_text` 和明确读文件工具，要求同一读取语句指向字面 `SKILL.md`。搜索、目录列举或只引用路径不计。复杂动态变量、脚本间接读取无法可靠恢复时不猜测。
4. 根据 `call_id` 在同一 session 内关联实际返回。输出可能是字符串，也可能是文本块列表；嵌套 JSON 中的换行、CR 和引号转义先解码。仅在返回正文出现与技能目录名相符的 YAML `name`、以及 `description` 时确认。本次抽查发现并修正了“引号/CR 转义造成成功正文漏计”。退出码为零、`Script completed` 或返回有内容都不能单独证明读到该技能。
5. 一个工具调用读取多个技能时，每个有匹配正文的技能各记一次；同一工具调用重复出现同一技能路径不重复计。主要指标按“session ID × 技能”去重，重复读取次数作为补充指标。
6. 对复制历史，按 `call_id + 工具名 + 参数哈希 + 原始事件时间` 全局判重，并归属到创建时间不晚于该调用的最早来源 session。本次未发现相同键的复制工具调用。若复制过程重写 call ID 或事件时间，本方法无法完全识别；它也不把不同子代理的独立调用合并成一次用户对话。
7. 技能使用目录 basename 归一，适配本地不同安装位置或插件版本目录。本次确认的 25 个名字中没有 `index` 等通用 basename，也未发现需要区分的同名技能目录；并未做跨版本内容一致性或技能同义词推断。未来存在同名不同技能时需要扩展命名规则。

## 保守缺失与解读限制

- 40 个“工具调用 × 技能”候选缺少成功证据，未进入确认计数。其中 5 个出现读取错误或未返回对应正文，35 个没有可匹配的技能 frontmatter。异步调用仅返回等待状态、超时、输出缺失或截断，都会保守排除；没有追溯拼接独立后续 `wait` 的输出。未确认不等于技能一定没有被读取。
- 另有 17 个含 `SKILL.md` 字样的工具调用未解析成明确的字面读取语句，其中包括搜索、列目录、路径引用和动态命令；这些也未计入。17 是工具调用数，40 是技能候选数，两者单位不同。
- 本地全局工作约定明确要求相关实施/排障任务读取 `proactive-problem-solving`。该配置会直接影响它的高频读取，不应把排名解释成自动选择偏好。
- 不同技能适用范围不同，且重复读取与对话长度、任务类型、配置和上下文刷新有关；排名不能用来比较效果、质量或投入产出。
- 这只描述一个人的本地可观测技能文件读取。它不是准确的全局自动调用率，不证明技能被遵守，不证明任务完成，不支持“使用后效率提升”的因果结论。没有未使用该技能的对照实验。

## 文件与隐私

可公开：`safe_aggregate.json`、`skills.csv`、`daily.csv`、本文，以及审核后的 `analyze_skill_reads.py`。公开数据只含技能名、日期、聚合计数和方法，不含用户内容、会话 ID、标题、项目路径、命令、工具原文、账号或凭据。

仅留本地：`private_evidence.jsonl`、`private_unresolved.jsonl`、`private_audit_summary.json`、`private_spot_checks.json`。私有文件保存必要哈希或本地源文件引用与行号，供核验；不保存命令、用户内容或返回正文。请勿随仓库公开这些私有审计文件。

## 复用

脚本只用 Python 标准库，无网络请求，不修改 sessions 或 installed skill。输入目录、输出目录、起止时间均由参数指定，没有把个人用户名或盘符写成默认配置。

```text
python analyze_skill_reads.py --sessions <session-directory> --output <audit-output-directory> --start 2026-09-29T00:00:00+08:00 --end 2026-10-06T00:00:00+08:00
```

`--utc-offset-hours` 控制按日展示的时区偏移（本次为 8）；脚本默认目标为 `proactive-problem-solving`，可用 `--target` 指定。复用时先检查本地 rollout 格式和是否有目录 basename 冲突，再使用公开聚合。
