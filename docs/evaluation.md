# 怎么比较实际效果

这个技能希望减少未经查证就把任务标记为“受阻”、没有新证据的重试，以及把能自行解决的步骤交回用户。目标是更可靠地推进任务，不是追求永远不受阻或永远不询问。

## 目前的数据能说明什么

公开案例展示的是同一工作记录里的**障碍状态 → 后续行动 → 可确认结果**。它们不是“关闭技能 → 开启技能”的对照。

| 观察到的障碍 | 后续结果 | 用户介入与结果边界 |
| --- | --- | --- |
| 后台停止候选遇到解析、路径和回执问题 | 检查错误和接口语义后修改候选；局部验证中后台实际退出，停止后自动重建被拒绝 | 子代理记录缺少完整委派和主对话，端到端接管次数未知；现行旧窗口未加载候选 |
| 旧格式表格不能读取；价格结论受到质疑 | 补齐读取能力，重新读取表头和原单元格，确认跨页口径差异与重复页，收窄结论 | 观察范围内有 1 次用户质疑/纠错；未观察到用户代做步骤，但不等于全过程零接管；完整预算未完成 |
| 发布前不知道启动与构建入口是否匹配 | 实际文件核对得到问题清单 | 该轮完整观察窗口内 0 次追加用户介入；是只读咨询交付，不是修复、运行或发布成功，也不代表项目全过程零接管 |

这些有限案例不能支持“效率提升 X%”“接管次数减少 X%”或总体解阻率。时间戳只能显示记录间隔，不能告诉我们不使用技能会花多久。缺失的介入记录记为未知，不记为零。

表格案例有一项可复核的局部用时：从确认旧格式读取依赖缺失，到首次成功读出两份原表，记录时间差为 **87.304 秒（约 87 秒）**，包含代理处理和工具等待。它说明该轮读取障碍随后被打通，不是节省了 87 秒，也不是完整预算的完成耗时。没有无技能基线，不能换算成效率提升。

## 推荐记录的指标

| 指标 | 记录口径 |
| --- | --- |
| 可避免的受阻 | 代理结束或要求用户接手时，仍有符合既有权限和硬约束、可自行查证的合理路线未检验。须逐例复核依据，不能仅凭出现“受阻”二字判定 |
| 用户纠错/催推进 | 为纠正明显偏题、重复已排除路线、过早停止或过强完成判断而发生的介入；一次事件的连续回复合计一次，并保留消息数 |
| 用户实际接管 | 用户替代理完成本可由现有工具和权限完成的步骤；与只提出纠正分开统计 |
| 必要询问或授权 | 只有用户能决定、不可自行查得的信息，或发布/付款等需要的授权；单列，不算可避免接管 |
| 实际完成结果 | 按运行前约定的文件、页面、进程或业务状态验收；记录完成、部分完成、合理待授权或未完成，不能用测试数替代 |
| 完成耗时 | 从明确任务开始到可核验结果的实际用时；同时保留工具/服务等待及人工介入。未完成任务保留时间上限和结果，不能当作更快完成 |
| 无效重试 | 同一假设或路线在没有新证据、没有实际进展的情况下重复；正常回归检查或不同假设的验证不算 |

需求新增、用户主动状态询问、外部服务故障和必要登录应另列原因。统计时先确定任务窗口；子代理片段或不完整历史不能代替用户任务全程。

## 做有／无技能对照时

1. 事先固定任务、源数据、权限、硬约束、工具、模型与推理等级、时间上限和验收条件。
2. 使用两个互不继承答案的干净会话和独立工作副本。一组不读取或启用此技能及等价项目规则，另一组显式读取同一版本的技能。保留两组共有的安全和权限约束。
3. 调换各任务的运行顺序，避免全部先跑一组。不能让第二次运行直接复用第一次的修复或答案。
4. 保存原始结果和介入事件。运行结束后按同一验收条件复核，尽量让结果复核者不知道分组。
5. 同时报告完成数、样本数、接管类别和耗时。只比较双方完成任务的耗时时，必须同时公开未完成任务，避免把更早放弃误写为更高效率。
6. 不挑成功案例替换失败样本；小样本和人为构造测试都应明确标注。模型或工具本来就能自行推进时，对照可能没有差异。

历史案例适合了解行为和边界；条件一致的重复对照才更适合估计改善。两者都需要用户要求的实际结果，不能由读取频率推导效果。

另见本次 [可重复增量对照及公开输入、输出](comparison.md)：结果没有显示接手请求收益，也没有证明稳定效率提升。它保留了相同宿主工作约定，不能当作完全无指导基线。
